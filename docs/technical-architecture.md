# 小学科学教育游戏平台技术架构

## 1. 建设目标

本项目采用“先完成可研究的单游戏闭环，再扩展课程资源”的建设方式。第一阶段交付四年级课程目录和《城市停电修复》四关游戏，形成学生进入、游戏操作、过程记录、教师查看和数据导出的完整链路。

## 2. 推荐技术栈

### 前端

- Next.js 和 TypeScript：统一管理学生端、游戏页面、教师后台和后端接口。
- Tailwind CSS：建立适合小学使用的统一颜色、字号、间距和响应式规则。
- React：管理关卡状态、提示层级、反馈和进度。
- SVG 与 HTML Canvas：用于电路连接、拖拽元件和轻量动画。首批电路任务优先使用 SVG，避免引入重型游戏引擎。
- Zustand：管理一次游戏过程中的关卡状态与暂存进度。

### 后端

- Next.js Route Handlers：提供班级、实验场次、学生进入、游戏事件和导出接口。
- Prisma ORM：统一操作本地 SQLite 和服务器 PostgreSQL，减少迁移时的代码变化。
- Zod：验证班级码、匿名学生编号和游戏事件数据。
- Auth.js：仅用于教师账号登录。学生不注册账号，通过班级码和匿名编号获得限时会话。

### 数据库

- 本地开发与单机演示：SQLite。
- 实验室服务器和正式课堂实验：PostgreSQL。
- 核心数据表：教师、班级、实验场次、匿名学生、游戏版本、游戏进度、游戏事件和问卷链接。

### 部署与运维

- Docker Compose：统一启动网站和 PostgreSQL。
- Nginx：提供 HTTPS、域名访问和反向代理。
- Git：`main` 保存可用于实验的稳定版本，功能开发使用独立分支。
- 每次正式实验冻结游戏版本号。事件数据必须保存对应版本，防止不同关卡逻辑的数据混合。

## 5. 《城市停电修复》过程数据

每次关键操作写入 `game_event`：

- 实验场次、匿名学生编号、游戏版本；
- 关卡、学习目标、事件类型和时间戳；
- 首次选择、正确与否、错误类型；
- 尝试次数、提示等级和提示后的下一步操作；
- 关卡开始、完成、中途退出和总用时。

教师端导出两类文件：

- `student_summary.csv`：每名学生一行，适合与问卷星前后测合并。
- `game_events.csv`：每次操作一行，用于分析学习过程和常见错误。

## 6. 开发顺序

1. 将现有静态演示迁移为 Next.js 项目，并保留已经确认的视觉风格。
2. 完成四年级目录与《城市停电修复》四个可玩关卡。
3. 建立 SQLite 数据库和过程事件接口。
4. 完成教师登录、活动创建、进度查看和 CSV 导出。
5. 开展小规模试玩并冻结实验版本。
6. 使用 Docker Compose 迁移到实验室服务器和 PostgreSQL。
