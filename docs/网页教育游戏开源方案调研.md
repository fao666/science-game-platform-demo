# 小学科学动态网页游戏开源方案调研

> 调研日期：2026-09-22  
> 项目目标：四年级科学“电路”单元；网页直接运行；有场景、角色、动画、连续操作与问题解决；能够记录学生的尝试、错误、提示和完成路径。  
> 来源范围：只采用项目官方 GitHub 仓库、官方文档和官方许可证。

## 结论先行

现有 Demo 的问题不是少几张素材，而是交互模型仍然是“网页表单 + 正误判断”。若要让学生感觉自己在修复医院，应把游戏主体改成持续运行的二维场景：角色移动、设备状态变化、电流动画、可拖拽工具、线路连接、环境反馈和多步骤任务都在同一个游戏循环里发生。

**最推荐的正式组合：Next.js/React 平台外壳 + Phaser 4 游戏层 + TypeScript 电路规则引擎 + 网站统一过程日志接口。**

- Phaser 负责医院地图、人物/机器人移动、镜头、动画、声音、拖拽、碰撞、粒子、电流流动和任务反馈。
- 自研的轻量电路规则引擎负责“哪些节点连接、回路是否闭合、是否短路、开关状态、材料能否导电”。四年级课程不需要工业级 SPICE 求解器，透明、可控、能对应教材概念更重要。
- Next.js 继续负责平台首页、年级目录、学生进入、教师后台、实验场次和数据导出。
- Phaser 通过事件总线向网页层发送结构化事件，再由现有后端保存，而不是把游戏封装为无法观察的黑盒 iframe。
- PhET 的电路仿真用于交互与科学表达的设计参照，必要时可作为独立拓展资源；不建议直接改造成主游戏。

这套组合最符合本研究的核心：既能做成真正的动态游戏，又能把每一步学习过程变成可分析的数据。

### 推荐排序

1. **Phaser 4 + TypeScript：正式主方案。** 综合游戏表现、网页集成、数据记录、许可与长期维护，最适合。
2. **GDevelop：快速玩法原型备选。** 非程序人员参与关卡编辑时有优势，但正式数据接入不如 Phaser 自然。
3. **Godot Web：复杂独立游戏备选。** 将来做 3D 或多端独立游戏时再考虑，当前偏重。
4. **PhET CCK：教学交互参照/独立拓展资源。** 不作为主游戏代码底座。
5. **H5P：测验与补充活动。** 适合形成性练习，不承担动态主游戏。
6. **CircuitJS1：工程与电路行为参考。** 不面向四年级学生直接使用。

## 方案对比总表

| 方案 | 开源许可 | 网页运行 | 动态游戏能力 | 过程数据接入 | 四年级适配 | 二次开发判断 |
|---|---|---:|---:|---:|---:|---|
| **Phaser 4** | MIT | 原生 HTML5/WebGL | 很强 | 很强 | **很适合** | 中等，推荐主方案 |
| **PhET CCK: DC** | GPL-3.0；品牌/互操作版另有限制 | 单文件 HTML 可部署 | 仿真很强、叙事较弱 | 普通版较难深度记录 | 概念适合，界面需裁剪 | 高，不建议直接改主游戏 |
| **CircuitJS1** | GPL-2.0-or-later | 浏览器运行 | 电路仿真强、游戏性弱 | 中等偏难 | 不适合直接给四年级 | 高，只宜技术参考 |
| **Godot 4 Web** | MIT | WebAssembly/WebGL 2 | 很强 | 中等 | 可做，但偏重 | 中高，当前不优先 |
| **GDevelop** | 核心和 HTML5 引擎 MIT | 可导出 Web | 强 | 中等 | 适合快速原型 | 低代码友好，但长期集成次于 Phaser |
| **H5P** | 核心 PHP 库 GPL-3.0；内容类型各自许可 | 嵌入 CMS/LMS | 中低 | xAPI 较好 | 适合练习，不适合主游戏 | 适合作为测验补充 |
| **PixiJS** | MIT | 原生 WebGL/WebGPU | 渲染强，游戏系统需自建 | 很强 | 适合定制仿真 | 中高；比 Phaser 多造轮子 |
| **Konva** | MIT | 原生 Canvas | 图形拖拽强，游戏系统弱 | 很强 | 适合电路图编辑 | 中等；适合编辑器而非场景游戏 |
| **Matter.js** | MIT | 原生 JavaScript | 物理碰撞强 | 很强 | 可作为局部辅助 | 不应承担电路逻辑 |

## 1. Phaser 4：推荐作为游戏主体

### 能做什么

Phaser 是面向桌面和移动浏览器的 HTML5 游戏框架。官方 API 提供场景、精灵、动画、输入、摄像机、灯光、粒子、补间和物理等系统；游戏对象可接收指针与拖拽事件，也可以发出自定义事件。这意味着医院停电不是一张静态底图，而可以变成一个持续运行的场景：灯光闪烁、角色行走、设备告警、机器人携带工具、导线随拖动变化、电流粒子沿闭合回路流动。[官方仓库](https://github.com/phaserjs/phaser)；[Game Objects 官方文档](https://docs.phaser.io/phaser/concepts/gameobjects)；[输入拖拽事件](https://docs.phaser.io/api-documentation/event/input-events)

### 许可证与活跃度

Phaser 使用 MIT 许可证，允许修改、分发和商用，但需要保留版权与许可文本。[官方许可证](https://github.com/phaserjs/phaser/blob/master/LICENSE.md) 2026 年仍在持续发布，官方仓库记录 Phaser 4.0 于 2026-04 发布、4.2 于 2026-06 发布，说明维护活跃。[官方发布页](https://github.com/phaserjs/phaser/releases)；[官方变更记录](https://github.com/phaserjs/phaser/blob/master/CHANGELOG.md)

### 部署和集成

它本质上是 JavaScript/TypeScript 依赖，可直接装进现有网页工程，把画布挂载在指定容器中，不必把整款游戏隔离为 iframe。Phaser 的事件系统与浏览器事件模型接近，适合在关键动作发生时调用平台统一的日志函数，例如：

```text
component_picked
wire_started
wire_connected
circuit_tested
short_circuit_created
hint_opened
fault_repaired
mission_completed
```

每条事件可附带学生匿名编号、关卡、元件、连接关系、时间戳、尝试序号和当时游戏状态。因此它在“游戏表现”和“研究数据”之间最平衡。[官方事件文档](https://docs.phaser.io/phaser/concepts/events)

### 难度与风险

二次开发难度为中等：要自己编排任务和电路逻辑，但代码、素材和日志完全掌握在项目内。建议固定一个明确版本，并先做一关纵向切片，再扩展关卡；不要一开始同时开发六个单元。

### 四年级适配结论

**最适合。** 可以把抽象电路知识藏进可见的任务后果里：接错线会短路冒烟，断路时电流粒子停止，合上开关后急诊室逐区亮起。学生是在推理和操作，不是在阅读答案按钮。

## 2. PhET Circuit Construction Kit: DC：最佳教学参照，不宜直接作为主游戏代码

### 能做什么

PhET 的 CCK: DC 是成熟的 HTML5 电路仿真，支持搭建电路并观察灯泡、电流等状态，科学表达和交互细节很值得参照。[官方仓库](https://github.com/phetsims/circuit-construction-kit-dc)；[官方在线版本](https://phet.colorado.edu/sims/html/circuit-construction-kit-dc/latest/circuit-construction-kit-dc_en.html)

官方开发说明显示，它可以构建为适合部署的单个 HTML 文件；但源代码依赖大量并列的 SceneryStack 仓库，构建和维护明显比普通 npm 游戏项目复杂。[CCK 官方构建说明](https://github.com/phetsims/circuit-construction-kit-dc)；[PhET 开发总览](https://github.com/phetsims/phet-info/blob/main/doc/phet-development-overview.md)

### 许可证与集成边界

CCK 源代码仓库为 GPL-3.0，若直接修改并发布衍生版本，需要认真履行 GPL 的源代码开放义务。[官方 LICENSE](https://github.com/phetsims/circuit-construction-kit-dc/blob/main/LICENSE) 同时，PhET 官方对网站发布的常规 HTML 模拟文件采用 CC BY-NC 4.0，并对商业使用、署名、标识和改编方式另有说明；因此“源码可见”不等于“任意复制发布所有官方成品和品牌素材”。[PhET 官方许可页](https://phet.colorado.edu/en/licensing) 更关键的是，用于深度互操作和数据访问的 PhET-iO 版本明确需要许可协议，不能把它当成普通免费遥测 API。[官方品牌与互操作许可说明](https://github.com/phetsims/brand)

普通公开版本可作为页面内独立活动或 iframe 资源，但要可靠捕获“学生拖了哪根线、何时形成短路”等内部动作并不自然。若 fork 源码加入日志，会同时面对 GPL、复杂依赖和后续同步成本。

### 活跃度与四年级适配

官方公共仓库累计大量提交，2026 年仍有维护活动；共享电路仓库持续用于 DC、AC 和虚拟实验室版本。[CCK Common 官方仓库](https://github.com/phetsims/circuit-construction-kit-common)

内容层面适合电路概念，但它更像开放实验台而不是“医院抢修”游戏，元件和自由度也可能超过四年级需求。**建议借鉴它的电流可视化、接点吸附、真实/符号视图和即时反馈，不直接把整套代码作为本项目核心。**

## 3. CircuitJS1：强电路模拟器，但年龄和架构不匹配

CircuitJS1 是浏览器电子电路模拟器，能动态显示电压和电流，采用 GPL-2.0-or-later。[官方仓库及许可证](https://github.com/sharpie7/circuitjs1)

它适合中学、大学或电子爱好者探索复杂元器件；界面、参数和电路表示对四年级学生过于专业，也缺乏角色、任务、场景和儿童反馈。直接修改会受 GPL 约束，且把它改成医院故事游戏的工作量可能高于自研轻量电路模型。

**建议：只作为电路行为和边界情况的技术参考，不嵌入学生主流程，也不复用其代码到闭源或不同许可的核心。**

## 4. Godot Web：能力强，但当前网站集成成本偏高

Godot 是 MIT 许可的完整 2D/3D 游戏引擎。[官方许可证说明](https://github.com/godotengine/godot/blob/master/COPYRIGHT.txt) 它可以导出 HTML 页面、WebAssembly 和资源文件，由 Web 服务器提供；Godot 4 Web 需要 WebAssembly 与 WebGL 2，官方推荐使用单线程 Web 导出以减少跨源隔离要求。[官方 Web 导出文档](https://github.com/godotengine/godot-docs/blob/master/tutorials/export/exporting_for_web.rst)

Godot 可以做出更像独立游戏的动画、地图和物理，但会形成一个相对独立的运行时。与 React/Next.js 平台之间通常要增加 JavaScript 桥或 iframe 消息层，过程日志、登录态和响应式页面集成比 Phaser 麻烦；导出体积和首次加载也更重。C# 项目在 Godot 4 目前不能导出 Web，因此需用 GDScript/C++ 路线。[同一官方 Web 导出文档](https://github.com/godotengine/godot-docs/blob/master/tutorials/export/exporting_for_web.rst)

官方 2026 年仍连续发布 4.6、4.7 和补丁版本，活跃度很高。[官方发布策略](https://github.com/godotengine/godot-docs/blob/master/about/release_policy.rst) **若未来要做复杂 3D 科学世界或同时发布桌面/移动端，可重新评估；当前单个二维电路游戏不值得引入这层复杂度。**

## 5. GDevelop：适合快速试玩，长期研究平台集成略弱

GDevelop 是面向 2D/3D/多人游戏的低代码开源引擎，使用事件系统组织玩法；其核心、HTML5 引擎、编辑器和扩展为 MIT 许可，导出的游戏不要求开源。[官方仓库与许可说明](https://github.com/4ian/GDevelop)

它支持精灵、粒子、灯光、碰撞、拖拽、路径寻找、物理和 JavaScript 扩展，并能发布为 Web 游戏。[官方文档](https://wiki.gdevelop.io/gdevelop5/) 对不熟悉代码的教师或设计者，修改动画和关卡比 Phaser 直观。官方仓库在 2026 年仍持续发布，维护活跃。[官方 Releases](https://github.com/4ian/GDevelop/releases)

局限在于导出物更像一个独立游戏包。要让每个内部动作稳定进入本项目的匿名学生日志，需要编写 JavaScript 扩展或网络事件，并约定与平台的消息协议；场景和事件表生成的工程也不如纯 TypeScript 方便代码审查、自动测试和多人 Git 协作。

**建议定位：** 如果导师想在短时间内比较两种玩法，可用它做一次性可玩原型；正式实验版本仍优先 Phaser。另需逐项检查使用的素材包许可证，不能把“引擎 MIT”误认为“素材都可自由使用”。

## 6. H5P：适合练习和测验，不适合承担动态主游戏

H5P 的优势是快速制作拖放、分支情境、互动视频、记忆游戏和题组，并能向宿主发送 xAPI 语句。[H5P 官方组织](https://github.com/h5p)；[H5P 与 xAPI 官方说明](https://h5p.org/documentation/x-api)

但 H5P 是内容类型与 LMS/CMS 集成生态，不是持续运行的游戏引擎。其通用 PHP 库为 GPL-3.0，平台需要实现 H5P 的框架接口、上传、存储和渲染等能力。[官方核心库与说明](https://github.com/h5p/h5p-php-library) 不同内容类型还可能有各自许可证，应逐个核对。

H5P 官方仓库在 2026 年仍更新多个内容类型，生态活跃。[官方 GitHub 组织](https://github.com/h5p) 但“把物品拖到正确位置”“答题后跳转”仍然接近用户不满意的点点点交互。

**建议：** 可用于课前预测、课后巩固或教师快速制作小练习；不作为《城市停电修复》的主游戏技术。

## 7. 其他值得保留的候选

### PixiJS

PixiJS 是 MIT 许可的高性能 2D Web 渲染引擎，支持 WebGL/WebGPU、鼠标和多点触控、图形、精灵和动态纹理。[官方仓库](https://github.com/pixijs/pixijs) 它很轻、与 React/TypeScript 集成自由，适合高度定制的科学可视化；GDevelop 的 Web 运行时本身也使用 PixiJS。

但 PixiJS主要解决“怎么画得快”，场景切换、任务系统、声音管理、输入抽象和常见游戏结构需要自行补齐。对于本项目，Phaser 已提供这些能力，所以 PixiJS 是备选而非首选。

### Konva

Konva 是 MIT 许可的 Canvas 交互图形框架，官方定位包括图形编辑器、白板、图表，原生支持事件、拖放、变换和动画。[官方仓库](https://github.com/konvajs/konva)

它很适合开发“自由摆放电池、灯泡并拉线”的电路图编辑器，也容易与 React 页面和日志 API 结合。但医院角色移动、粒子、音效、镜头和关卡氛围都要额外搭建。若最终研究只保留纯电路搭建器，可考虑 Konva；既然目标是动态故事游戏，Phaser 更合适。

### Matter.js

Matter.js 是 MIT 许可的浏览器二维刚体物理引擎。[官方许可证](https://github.com/liabru/matter-js/blob/master/LICENSE) 它可用于工具箱掉落、物体碰撞等局部效果，Phaser 也能与物理系统配合。但“导线是否形成闭合回路”不是刚体物理问题，因此不能用 Matter.js 代替电路规则引擎。

### SceneryStack

Scenery 是 PhET 使用的 HTML5 场景图，可用 SVG、Canvas、WebGL 等方式显示，库本身为 MIT 许可。[官方仓库](https://github.com/phetsims/scenery) PhET 官方也建议非 PhET 团队通过 SceneryStack 包开发新仿真。[官方开发总览](https://github.com/phetsims/phet-info/blob/main/doc/phet-development-overview.md)

它在科学仿真、无障碍和精确可视化方面有价值，但生态、学习曲线和项目结构比通用 Web 游戏框架特殊。本项目已经有 React/Next.js 方向，又需要明显的游戏叙事和动画，因此没有 Phaser 合适。

## 推荐技术组合的具体形态

```text
科学教育平台（Next.js / React）
├─ 登录、年级目录、课程页、教师后台
├─ 实验场次与匿名学生编号
├─ 统一日志 API 与 CSV 导出
└─ 游戏容器
   └─ Phaser 4《城市停电修复》
      ├─ 医院地图与角色/机器人
      ├─ 动画、声音、粒子、镜头和碰撞
      ├─ 任务状态机
      ├─ TypeScript 电路图模型
      └─ GameEventBridge → 平台日志 API
```

### 电路模型建议

首版不要追求电阻、电压和电流的连续数值求解，先用教材可解释的图模型：

- 节点：电池正负极、灯泡两端、开关两端、设备端口。
- 边：导线或能导电的材料。
- 元件状态：已安装、损坏、开关开/关、导体/绝缘体。
- 核心判定：是否存在从电池正极经负载返回负极的有效路径；是否出现绕过负载的短路路径；指定设备是否接入。
- 视觉反馈：闭合回路后沿有效边播放电流粒子；设备逐帧启动；错误连接触发保险丝、火花或警告，但不给出直接答案。

这种模型足以覆盖四年级“点亮小灯泡、简单电路、开关、故障检测、导体与绝缘体”，也便于解释和记录。若以后进入高年级定量电学，再考虑更完整的求解器。

### 第一关应该怎样变成真正的游戏

1. 学生控制维修机器人在停电医院中移动，查看急诊、配电间和走廊的异常。
2. 到护士站获取任务，通过闪烁图标、声音和人物动作理解“急诊照明必须恢复”，而不是读大段说明。
3. 在配电间拾取电池、灯泡、开关、导线和可能混入的无关物品，受工具箱容量限制。
4. 接线时导线端点实时跟随手势，靠近端子会吸附；电池装反、断路、短路都产生不同动态反馈。
5. 学生主动按下测试按钮或合上开关；系统运行电路模型，再把结果映射到医院场景：电流流动、灯光亮起、设备启动、人物恢复行动。
6. 失败不弹出“答案错误”，而通过场景现象提供证据，引导学生回到线路检查。
7. 后续关卡复用医院地图，但改变故障：松脱接点、损坏灯泡、开关位置不合理、材料导电性筛选，形成连续故事。

## 不推荐的实施方式

- 不建议直接把 PhET 或 CircuitJS iframe 嵌入页面后就称为自研教育游戏：情境、任务和过程数据无法充分控制。
- 不建议继续用 DOM 卡片模拟游戏主体：即使增加动画，本质仍是页面交互而非游戏循环。
- 不建议首版使用 Godot 做 3D：加载、资源制作和网站桥接会扩大项目风险，却不直接提升电路学习效果。
- 不建议为了“科学准确”一开始接入完整电子仿真器：四年级核心是回路与证据推理，复杂参数会增加无关认知负荷。
- 不建议依赖未经核验许可证的 GitHub 游戏素材或项目模板；引擎许可与素材许可必须分开记录。

## 最终决策建议

1. **正式主线：采用 Phaser 4。** 先开发一关 8–12 分钟的“急诊室复电”纵向切片，验证操控感、科学逻辑和日志质量。
2. **科学设计参照：研究 PhET CCK。** 学习其接线吸附、电流表达和即时反馈，但不直接 fork 为主游戏。
3. **电路逻辑：自研小型图模型。** 保持与四年级教材目标一一对应，并为每次状态变化产生可分析事件。
4. **平台集成：游戏与 Next.js 同仓库、同域部署。** 避免 iframe 黑盒；通过统一事件桥接进入教师数据后台。
5. **H5P/GDevelop 的位置：** H5P 留给补充练习；GDevelop仅在需要非程序人员快速验证另一种玩法时使用。

因此，下一步不应再寻找一款“拿来即用的医院电路游戏”直接套壳，而应利用成熟开源游戏引擎搭建自己的动态任务，同时借鉴成熟电路仿真的科学交互。这样既不会重复造渲染和动画轮子，也不会牺牲论文所需要的教学控制与过程数据。
