# 小学科学教育游戏平台 MVP 产品设计文档

版本：0.1  
状态：方向确认稿  
适用阶段：本地原型开发与首次课堂试用

## 1. 产品概述

本项目拟开发一个面向小学科学学习的网页游戏平台。平台整体采用适合小学生的卡通化设计，提供一年级至六年级的年级目录和科学游戏入口；教师可以创建班级实验活动、管理学生进入情况，并导出游戏过程数据。

MVP 不追求一次建成完整的游戏资源平台，而是先完成“一款可用的游戏、一次可实施的课堂实验、一套可分析的数据”的闭环。

首款游戏暂定为四年级科学电路单元《城市停电修复》。

## 2. 产品目标

1. 将小学科学教学目标转化为可操作的游戏任务和即时反馈。
2. 支持学生通过网页完成科学游戏，不要求安装软件。
3. 支持教师组织班级活动、查看进度和导出学习过程数据。
4. 为游戏化学习效果研究提供稳定、可匹配、可分析的数据。
5. 为后续增加其他年级和科学游戏保留扩展结构。

## 3. 目标用户

### 学生

- 通过班级码和匿名学生编号进入游戏。
- 阅读任务、完成关卡、获得提示和反馈。
- 不需要自行注册账号，不收集非必要个人信息。

### 教师或研究者

- 登录教师后台。
- 创建班级和实验场次。
- 获取班级码并控制游戏开放状态。
- 查看学生完成情况和基本统计。
- 导出原始过程数据与学生汇总数据。

## 4. 产品结构

```text
平台首页
├─ 年级目录
│  ├─ 一年级
│  ├─ 二年级
│  ├─ 三年级
│  ├─ 四年级
│  │  └─ 城市停电修复
│  ├─ 五年级
│  └─ 六年级
├─ 学生进入
│  └─ 班级码＋匿名学生编号
└─ 教师后台
   ├─ 班级管理
   ├─ 实验场次管理
   ├─ 学生进度
   ├─ 游戏数据统计
   └─ 数据导出
```

MVP 只正式发布四年级《城市停电修复》。其他年级保留目录结构，未发布内容显示建设中或不在学生端展示。

## 5. 学生端主要功能

### 首页和年级目录

- 使用大字号、圆角卡片和卡通科学元素。
- 支持电脑和平板浏览。
- 清晰展示游戏适用年级、学习主题和预计时间。

### 活动进入

- 学生输入教师提供的班级码和匿名编号。
- 系统验证活动是否开放。
- 学生刷新或临时退出后可以继续当前进度。

### 游戏体验

- 提供简短操作教程。
- 每个关卡只解决一个核心科学问题。
- 正确时给予积极反馈，错误时给予原因提示。
- 游戏结束后展示完成结果和已学习的知识点。

### 帮助系统

MVP 不接入开放式 AI 对话，也不跳转外部 AI 网站。游戏设置卡通维修机器人，提供经过教师审核的三级固定提示：

1. 关注方向；
2. 局部线索；
3. 原理解释。

系统记录学生请求提示的关卡、时间、等级和提示后的操作结果。

## 6. 首款游戏设计

游戏名称：《城市停电修复》  
适用内容：四年级科学电路单元  
核心情境：城市多个区域发生停电，学生扮演小小电力维修员，通过科学判断完成维修任务。

| 关卡 | 学习目标 | 游戏任务 |
| --- | --- | --- |
| 点亮医院 | 判断闭合电路 | 正确连接电池、导线和灯泡 |
| 修复图书馆 | 诊断简单故障 | 找出断路、接触错误或开关状态问题 |
| 安装走廊开关 | 理解开关作用 | 将开关安装在合适位置并控制通断 |
| 安全维修 | 区分导体与绝缘体 | 为连接部分和电线外层选择合适材料 |

游戏关卡应与学习目标一一对应，学生只有运用相应科学知识才能完成任务。

## 7. 教师端主要功能

### 班级与活动管理

- 创建班级。
- 创建一次游戏活动并生成班级码。
- 设置活动开始、暂停和结束状态。
- 选择游戏版本，避免不同版本数据混合。

### 进度查看

- 查看学生是否进入和是否完成。
- 查看学生当前关卡。
- 标记中途退出或数据异常的情况。

### 数据概览

- 各关完成率和首次正确率。
- 平均尝试次数、提示次数和完成时间。
- 各学习目标的表现情况。
- 常见错误类型。

### 数据导出

至少导出两份文件：

- `student_summary.csv`：每名学生一行，包含关卡得分、完成时间、尝试和提示次数等汇总数据。
- `game_events.csv`：每次操作一行，保留完整的原始行为日志。

## 8. 前后测与问卷安排

MVP 不自建问卷系统。正式前测、后测和学习体验问卷使用问卷星完成。

教师后台可预留前测、后测和体验问卷链接配置，但网站不需要直接读取问卷星答案。问卷星数据与游戏数据通过同一匿名学生编号匹配，之后在 Excel、SPSS 或 Python 中合并分析。

过程数据用于解释学生在游戏中如何学习，前后测用于判断学习效果，体验问卷用于判断兴趣和课堂感受，三类数据不能互相替代。

## 9. 过程数据要求

游戏至少记录以下数据：

- 匿名学生编号、班级和实验场次；
- 游戏版本、关卡和任务编号；
- 学习目标编号；
- 学生第一次作答或操作；
- 正误结果和错误类型；
- 尝试次数与完成时间；
- 提示使用次数和提示等级；
- 关卡是否完成；
- 操作时间戳。

研究中建议使用“学习过程数据”“游戏行为日志”或“细粒度交互数据”等表述，不将小样本课堂数据直接称为大数据。

## 10. 视觉与交互方向

- 整体风格为卡通化的儿童科学探索主题。
- 首页借鉴游戏门户的卡片式目录，但避免信息过密。
- 主色建议使用蓝色、橙色和绿色。
- 每个页面只突出一个主要任务。
- 按钮和文字适合小学生阅读和点击。
- 反馈动画简短，避免频繁闪烁和过度音效。
- 不包含广告、充值、聊天、评论和陌生人社交。
- 素材使用原创、AI 生成或授权资源，不直接使用来源不明的教材截图和网络图片。

## 11. 技术与部署方向

- 网页应用：Next.js、TypeScript、Tailwind CSS。
- 本地开发数据库：SQLite。
- 实验室服务器数据库：PostgreSQL。
- 部署方式：Docker。
- 版本管理：Git。
- 学生端优先兼容学校常用的 Chrome、Edge 和平板浏览器。

正式开发时建议建立独立 Git 仓库，保留 `main` 稳定分支，功能使用独立分支开发。图片、音频和游戏素材统一归档并记录来源。

## 12. MVP 不包含的功能

- 通用 AI 对话和外部 AI 网站链接；
- 多学科和大量游戏；
- 家长端、校级管理端和复杂权限系统；
- 学生自由注册和真实姓名账户；
- 排行榜、积分商城和社交功能；
- 自动完成统计分析或生成论文结论；
- 手机原生应用；
- 复杂的个性化推荐和多智能体系统。

## 13. 开发里程碑

1. 完成项目基础、首页和年级目录。
2. 完成班级码进入和学生进度保存。
3. 完成《城市停电修复》四个关卡及固定提示。
4. 完成教师后台、过程日志和 CSV 导出。
5. 开展小规模试玩，修复可用性与数据问题。
6. 冻结正式实验版本并记录版本号。

## 14. MVP 验收标准

- 教师可以创建班级活动并获得班级码。
- 学生可以使用匿名编号进入并完成四个关卡。
- 页面在电脑和平板上可以正常使用。
- 页面刷新后不会丢失主要进度。
- 每次关键操作都能形成可追踪的行为日志。
- 教师可以查看完成状态并导出数据。
- 数据能够通过匿名编号与问卷星前后测匹配。
- 首次课堂试用时，不需要教师或学生安装额外软件。

## 15. 后续迭代方向

- 增加其他年级和科学游戏。
- 增加问卷星数据导入与自动匹配。
- 增加更细致的学习困难诊断图表。
- 在游戏效果得到验证后，开发受控 AI 提示助手，并把“固定提示与 AI 提示的差异”作为新的研究问题。
