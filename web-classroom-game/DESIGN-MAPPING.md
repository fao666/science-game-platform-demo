# 教材目标—游戏机制—验证证据

教材：用户提供四下第4课，印刷29—30页，PDF34—35页。本轮已渲染核对：提出故障想法、制作检测器、每次检测前自检、排查记录、交流依据，禁止检测家用电器。后续开关等课的知识不作为本课新增学习目标。

| 教学目标/难点 | 学习行动 | 游戏机制 | 检查证据 |
|---|---|---|---|
| 同一不亮现象有不同原因 | 提出多个原因，允许修正 | 三个作品分别连接/灯泡/导线故障 | 初始及后续猜想事件 |
| 工具自身可靠性 | 构建参考闭合回路，拆开关、自检 | 拖端点连接，拓扑判定灯亮，拆开关与触碰检测端 | 接线、自检记录；绕过灯泡的短路不能成功 |
| 根据现象而非外观判断 | 自由选择检测部位 | 同一场景拉近实验桌，探针接触自动判定 | 检测对象/顺序/亮灭 |
| 证据支持判断 | 比较检测现象与修复复验，承认判断的不确定性 | 调查本可选引用记录，不以固定证据组合阻止结案 | 区分修复成功、原因证据支持、多个调整难以归因；正常对象记录为补充 |
| 修复必须复验 | 调整/更换，供电观察 | 错换正常对象仍不亮，修复后灯光改变 | 修复行为及复验事件 |
| 方法迁移 | 器材换位后独立调查 | 第三例镜像布局 | 路径、求助和结案证据 |
| 交流与反思 | 解释原因与依据 | 报告、交还摊主、NPC回应 | 原文说明，教师人工评价 |

## 转化与生产过程

教材核对→映射目标与行动→检查情境合理性（医院改校园游园会）→定义三个病例与状态模型→生成角色场景→实现Canvas交互与DOM记录→规则测试→浏览器试玩→修正接点/探针抢事件→补NPC与UI比例→后续儿童试教。

AI负责草拟和实现，人负责情境、科学内容和教学体验判定。这个版本是方法可行性样本，不构成学习增益或跨教师可复用的验证。skill在实际试教迭代后再提炼。

## 待验证

目前自检状态在进入实验桌及修复后清除；连续检测仍允许沿用同次自检。教师需提醒教材要求每次检测前自检，后续决定是否强制每次检测。短路为离散图模型，不模拟电流大小。前后测另行设计。角色目前没有完整朝向/拿取动作组，作品在实验桌共用基础器材布局，需由试玩反馈决定下一步深化。
